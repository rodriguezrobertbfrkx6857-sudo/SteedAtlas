# 首批五匹名马数据库说明

本包已经新增一套“视频工厂可优先引用”的五匹名马知识库：

- 赤兔
- 的卢
- 汗血
- 绝影
- 乌骓（同时兼容用户输入“乌雎”“乌椎”“骓”）

## 文件位置

- 知识库数据：`backend/data/legendary_horses_top5.json`
- 入库脚本：`backend/scripts/seed_top5_legendary_horses.py`
- 工作流引用逻辑：`backend/app/services/workflow_tasks.py`

## 数据内容

每匹马包含：

- 名马基础信息：名称、别名、主人、朝代、史料来源
- 名马生平故事
- 主人一生故事摘要
- 视频创作故事锚点
- 分镜关键词、视觉关键词、情绪弧线、避坑项
- `gpt-image-2` 华丽图片提示词
- 生成后的图片文件名

## 如何写入数据库

进入网站后端目录后运行：

```bash
python scripts/seed_top5_legendary_horses.py
```

脚本会做两件事：

1. 把五匹马的完整故事写入 `horses` 表。
2. 使用已配置的 `VIDEO_FACTORY_IMAGE_*` 接口生成五张华丽图片，并保存到：

```text
generated/horse-library/
```

生成后的数据库图片路径类似：

```text
/generated/horse-library/chitu-luxe.png
```

如果只想先写数据库、不调用图片 API：

```bash
python scripts/seed_top5_legendary_horses.py --no-image
```

## 视频工厂如何引用

工作流运行时会优先读取：

```text
backend/data/legendary_horses_top5.json
```

当主题或马名命中五匹马之一时，脚本节点、分镜节点、关键帧节点、Veo 节点都会优先使用这份资料里的：

- `story`
- `horse_life_story`
- `owner_life_story`
- `hook`
- `conflict`
- `visual_keywords`
- `shot_beats`
- `prompt_guidance`
- `avoid`
- `image_url`

成片输出缩略图也会优先使用 `generated/horse-library` 下的新图片。

## 常见问题

### 输入“乌雎”为什么会变成“乌骓”？

代码里做了别名归并，`乌雎 / 乌椎 / 骓` 都会指向 `乌骓`，避免检索不到。

### 生成图片失败怎么办？

先确认 `.env` 里图片接口完整：

```text
VIDEO_FACTORY_IMAGE_API_KEY=
VIDEO_FACTORY_IMAGE_BASE_URL=
VIDEO_FACTORY_IMAGE_MODEL=gpt-image-2
VIDEO_FACTORY_IMAGE_API_PATH=/images/generations
```

然后重新运行：

```bash
python scripts/seed_top5_legendary_horses.py
```

已有图片不会重复生成，脚本只会补缺失文件。

### 运行工作流还是没用到新资料怎么办？

因为工作流知识库加载函数带缓存，修改数据文件后需要重启后端服务。重启后再运行视频工厂即可。
