## R1：修复检索与引用边界（必须）

### 1. Top-k 满额时仍需保留已知反证

当前 `EvidenceSearch.search` 在填满 hits 后才追加同 proposition 的证据，可能因为 limit 已满完全跳过反证。先复现，再在一个统一 selection 阶段分配实体代表、明确反证和相关性名额。最终 results 必须满足请求 limit，不用无限增大 k 掩盖问题。

必须覆盖：
- 高相关支持段落填满 Top-k，但同命题反证词法分数低；系统不可默默给出无分歧答案。
- 多实体数量超过 limit；不能结果越界，应明确覆盖不足或要求缩小范围。
- 源文同名不等于同实体；未知 proposition 不伪造冲突。
- history/literature/all 范围与来源权限贯穿 candidates、results、答案展示。
- 反证不足以展示时，在 evidence metadata 中标记截断/未完全覆盖，不能宣称“没有反证”。

### 2. 不用大量原文替代直接回答

保留原文与归属式语气，在不调用外部模型的模式下加简短可解释摘要：识别了什么实体、在哪部作品找到明确提及、当前原文不能证明哪些问题前提。真正文本证据与文化寓意/商品推荐继续隔离。

机器验证只证明引用和版本可核对，不推断“出生年月”“最后结局”“唯一主人”等不存在的关系。长段落展示可折叠，但原始 span、原文与定位可查看，不能通过删改引文制造支持。

### 3. 受控 Agent 行为

目前规划是规则。保留真实 trace、预算和页面限制；失败、超时、权限拒绝都应有结构化日志，不用 success 覆盖失败。无模型时保持 RULE_BASED，不重命名为 LIVE_LLM。允许自主资料获取，但不让任何登录用户无上限触发全库抓取；对公共/共享环境补每用户及全实例获取上限、互斥或排队。

## R2：演示前预检、刷新与离线降级（必须）

现有机器引文健康观察有效期七天，但尚未自动刷新。实现一个命令明确检查：Python/Node/FFmpeg、中文字体、端口、数据库副本、当前有效引用数、来源观察时间、许可和权限、缓存完整性、来源 manifest、是否启用费用路径。

建议增加 `scripts/resume_demo_preflight.py --database <项目内副本> --offline` 和显式的有限刷新参数；具体名称可按现有工具复用。预检默认只读，不隐式触发付费服务和原库迁移。需要更新时使用现有官方 API、限速/maxlag/请求预算，记录 FETCHED 与 CACHE 的区别。

必须分别处理：
- 临时网络不可用：允许浏览已保留的许可有效快照，标明快照/最后观察时间和非实时状态；能否作为“当前可用机器引文”按明确政策决定。
- 内容哈希/版本不匹配：禁止错误引用。
- 许可限制、私有化、撤回：必须 fail closed，离线模式也不能绕过。
- 来源缓存缺失：报告具体缺少哪个快照和如何合规重建，不能生成假原文。

不允许用“取消七天限制”“改 checked_at 为当前时间”“永远 AVAILABLE”来假修复。可将固定快照完整性与来源实时可用性分成独立字段，但需要边界测试和准确 UI 标识。
