# 三条创新假设与可复现实验（严禁杜撰结果）

## 研究主线 A：自适应 Agent 任务调度
**H-A**：在质量不下降超过预注册容差的前提下，按需角色调度比“固定所有 Agent”减少模型调用、延迟和人工返工。
- Baseline S0：单 Agent 一次规划 + typed tools。
- S1：固定 Research→Narrative→Director→Review→Repair（或等价严格定义的全量角色链）。
- S2：按证据覆盖/变更/风险的确定性自适应角色调度。
- 任务集：完整资料生成、已写脚本做镜头、修改字幕、证据冲突、素材缺失、跨场景关系冲突。含匿名人工定义与合成案例，显式分开。
- 主要指标：可接受任务比例、未支持事实数、人工编辑次数、LLM 调用次数/token、端到端延迟、循环上限触发率。无 LLM 时只测规则控制器，不得声称智能推理效果。
- 固定模型版本、温度（若 API 支持）、提示模板、任务输入和数据版本；比较样例应盲审。

## 研究主线 B：Scene Bible 一致性
**H-B**：结构化全局与逐场景约束可减少剧本/分镜在跨镜头人物、事件与时代上的矛盾。
- B0：无 Scene Bible，只用脚本独立规划每一场。
- B1：仅全局提示词/整体风格声明。
- B2：结构化 Scene Bible + continuity constraints + reviewer findings。
- 指标：每十场景矛盾数、人工修订次数、审查者一致性、可接受分镜比例、额外延迟。
- **限制**：仅凭文本与元数据的实验不能证明真实生成视频帧的一致性；有真实画面检测才可讨论多模态一致性。

## 研究主线 C：证据感知的局部更新
**H-C**：在正确性优先条件下，显式证据依赖及保守失效判定可以减少无用重建，同时降低不安全素材复用。
- R0：修改后全量重跑。
- R1：任务检查点恢复。
- R2：普通 DAG 节点指纹和内容哈希缓存。
- **R2+ 强基线**：DAG + 所有可见知识版本/状态/元数据作为依赖，含保守失效策略。
- R3：引入显式 evidence-to-artifact 类型依赖、认识论状态约束、语义未知 REVIEW_REQUIRED 的恢复策略。
- 注意：R3 不能通过特意让 R2 缺少必要版本字段来“赢”；必须对 R2+ 定义公平。
- 场景变化：封面、字幕、旁白、某一幕视觉素材、历史日期修订、文学标签变更、证据撤回、全局 Scene Bible、源文件丢失。
- 指标：`unsafe_reuse_rate`、`false_invalidation_rate`、`rebuild_node_count`、`CPU render_seconds`、`review_minutes`、系统总 wall-clock，以及正确性守卫触发。

## 测试集、统计与结果管理
- 实验数据必须保存明确 schema、任务版本/真实媒体哈希、随机种子、变更历史与 Gold label 来源。
- 3 个旗舰名马只够演示，无法自然证明强实体泛化；如要声称对未见实体有效，按实体划分 dev/test 并补足独立实体。
- 报告样本数、置信区间、失败与无显著差异结果；探索性实验不得包装为预注册假设。
- 当数据不足时仅发布 POC 与定性观察，不编造数值效果，不声称投稿成功。
- 自动评审不能替代人工历史支持核验；指标分“有证据支持”与“史实真实性”；若采用另一模型评测，说明相互依赖与误差。
