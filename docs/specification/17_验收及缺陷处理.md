# 严格验收、故障处理和最终交付格式

## 最终硬性门禁（全部列出 PASS / FAIL / BLOCKED）
| Gate | 要求 | 证据 |
| --- | --- | --- |
| A0 | 有实际授权仓库及当前 commit/branch 记录 | `git status`、基线报告 |
| A1 | 安全 P0 修复 | 回归用例、权限/上传/路径验证 |
| A2 | 前端源代码可构建、主要页面可操作 | 构建日志+浏览器检查 |
| A3 | 原有业务与数据保留 | 兼容测试、迁移前后数量对比 |
| A4 | 史料来源/断言可审核、有版本、有引用 | 查询/审核/引用验证 |
| A5 | 工作台存储真实 Project/Timeline | 保存刷新回放 API 测试 |
| A6 | **无本地 GPU、无视频模型、无 LLM 凭据，能真实 CPU 导出 MP4** | `ffprobe`、decode、真实文件与可用下载 |
| A7 | 工程任务真正 DAG 执行，有 checkpoint/retry/cancel | 故障注入及恢复证据 |
| A8 | Agent 模式、提案、权限、决策记录完整 | LIVE/Manual/Mock 区分+trace |
| A9 | 修改字幕与历史断言可判定影响范围 | 依赖图、保守三值失效测试 |
| A10 | OSS License / notices 可审计 | SPDX/commit/pinned deps + provenance |
| A11 | 创新实验不伪造结果 | 对照环境/真实数据/失败结果 |
| A12 | 可运行部署文档和回退计划 | 独立重建步骤、DB 备份恢复 |

## 失败时怎么处理
1. 测试 FAIL：标记 P0/P1/P2、根因、影响、修复方案、复现命令，优先安全/数据正确性，再修 UI；修复后必须重跑相关回归。
2. 外部凭据/收费/部署 BLOCKED：不得触发未知费用、不得伪造测试；保存最小 mock contract 和接口，并继续不依赖此项的阶段。
3. OSS POC FAIL：说明不采用理由，按 ADR 回退另一候选；不用再整合第二套完整产品。
4. 老功能回归 FAIL：优先修复兼容层/Feature Flag，而不是直接废弃旧页面。
5. 错误证据/历史叙述：保留原始来源、明确审稿标注，必要时下架相应公开展示；不让 Agent 自行修正历史事实。

## 最终报告必须真实包含
- 仓库 commit/branch、变更文件与模块列表。
- 功能矩阵：已完成/部分完成/未开始、对应测试证据。
- 数据迁移摘要（旧数据保留/新表建立/回滚验证）。
- React/TS 构建、pytest、Playwright、视频 FFprobe、并发/恢复测试的命令与结果。
- Agent 具体执行轨迹、工具调用、Proposal/审核记录，实际模式（LIVE/RULE/MOCK/MANUAL）。
- 视频演示：输入素材清单、时间轴 JSON、最终 MP4 路径/哈希/媒体参数、SRT；如当前交付环境无法生成文件，则明确阻塞，不虚构路径。
- 许可证清单、所有外部组件版本、版权风险、未解决安全/性能问题。
- 研究结果：实验样本、基线、消融、结果（若有）与不成立假设；未运行的实验不展示漂亮图表。
- 所有需要用户后续授权的具体事项集中记录，避免逐件打断。

## 验收与“完成”的界限
Sol 的工作必须能够被另一个开发者在独立工作区复现。不能把完成任务单、截图中的静态 UI、伪任务事件或过期的下载链接当成系统可用的证据。最终是否可发布由用户决定。
