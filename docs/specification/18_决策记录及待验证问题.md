# 决策日志与前置事实（Sol 需据实更新）

## 已确定 ADR（不能反转用户目标）
- ADR-1：Web-first，CPU-first，默认无 GPU、无训练、无视频模型。
- ADR-2：FastAPI + SQLAlchemy 主业务后端，避免微服务化。
- ADR-3：保留原有资料、资产、抽卡/收藏等现有业务，不清理历史文件作为“升级”。
- ADR-4：单一 Creative Project / Timeline 与任务状态来源。
- ADR-5：Agent 输出仅为 Proposal；不可自授权、不可冒充真实外部执行。
- ADR-6：历史知识/文学/争议类别分开；证据依赖失效保守优先。
- ADR-7：开源组件先 POC/许可证，避免同类引入多个主库。
- ADR-8：不进行需要支付费用的云端调用、公开部署和不可逆删除，除非用户明确授权。

## 执行期必须核实（不能从理论报告推断）
1. 仓库目前实际的唯一工作目录和是否已有更近期分支？
2. 前端 React 源码是否能恢复，已有构建器/脚手架/设计系统是什么？
3. 100 匹档案的数据字段/来源质量是否满足引用级结构化？
4. 当前历史媒体、上传工具、FFmpeg 编解码器和字体可用情况？
5. 当前 Redis/SQLite/PG 部署规模及迁移需求？
6. 旧 n8n/Webhook 是否仍为必须保留的兼容功能？
7. 原有用户认证体系是否有全局路由权限，不得仅据单文件结论判断漏洞已经可利用。
8. React Flow/Tiptap/Timeline Editor 的当前版本与已安装框架兼容性？
9. Render 是否必须使用浏览器帧捕获？先用现有 FFmpeg POC 证明或否定。
10. 创作作品的图片、配音、现代史料具体版权是否清晰？

## 实施风险排序
- P0：源码/数据库丢失、权限绕过、任意路径/SSRF、私有资产公开、无法恢复。
- P1：视频无法真实导出、任务重启丢失、用户编辑丢失、证据误标为史实。
- P2：性能不足、移动端交互、Agent 额外调用过多、第三方库升级兼容。
- P3：过度的学术高级指标、AI 模型本地部署、非核心商业增长功能。
