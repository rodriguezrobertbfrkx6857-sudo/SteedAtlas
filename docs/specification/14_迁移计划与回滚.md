# G0–G8 连续执行、门禁与回滚策略

## G0：真实环境、只读审查与回退点
- 读仓库内容/工作树/测试状态，记录 commit、branch、dirty diff、启动脚本、前端源代码与资产位置；在获授权的工作区创建专用升级分支或等价回退点。
- 备份 DB schema+数据、媒体清单、前端静态构建、环境配置的**非敏感模板**。可用哈希检验；保留旧版部署方式。
- 输出 `G0_BASELINE.md`、`FEATURE_MATRIX.csv`、`RISK_REGISTER.md`、`ROLLBACK_PLAN.md`。**不因未调查完成而破坏原文件**。
- Gate：原功能 inventory 和启动测试结果明确；权限/依赖障碍真实记录。

## G1：安全与基础工程
- 修复 P0 风险（auth、任意路径、默认密钥、SSRF、私有文件访问），引入 pytest/CI/格式检查和最小端到端 smoke。
- Gate：P0 对应回归测试通过，无 secrets/个人数据进入日志。

## G2：前端工程与视觉系统
- 优先恢复原 React 源码，保留现有 URL；逐步统一导航、设计 token、组件、响应式和无障碍。
- Gate：首页/名马/用户/旧业务路由可用；Playwright 截图与页面操作验证；不会用压缩 JS 直接长期维护。

## G3：知识、中文搜索与审核
- 新增 Source/Passage/Claim 不可变版本、引用 viewer、BM25+别名、权限后台、选定 3 个高质量样例。
- Gate：100 条基础档案不丢失；引用可定位；史实/文学区别可见；B0/B1 评测有记录。

## G4：统一创作工程与 CPU 视频工厂
- 项目/剧本/SceneBible/分镜/资产/时间轴统一 schema；手动编辑与上传，原 FFmpeg 适配、SRT/MP4 导出；真实素材权限与版权。
- Gate：关掉所有 AI Provider、普通 CPU 真实视频导出、ffprobe 校验、项目重载和历史版本；不允许 `mock://` 视为完成。

## G5：可靠 DAG 与 Worker
- 独立任务 Worker，DAG 编译器、节点状态和租约、持久化、重试、取消、恢复、审计；旧任务兼容。
- Gate：正常运行、进程崩溃、重复事件、旧租约、文件缺失、版本冲突测试通过。

## G6：Agent 创新功能与局部恢复
- 角色协议、确定性 Controller、Proposal → Validation → Commit、审查门、Explainable Trace、三值依赖影响判断。
- Gate：无 LLM 模式如实标注且可手动工作；有授权 Provider 时真实 trace 有内容且可审计；局部修改不会破坏未影响的产物。

## G7：实验、性能、界面体验
- 运行 B0/B1、S0/S1/S2、R0/R1/R2/R2+/R3 的离线/适用实验；报告负结果和置信区间；无 GPU/付费自动触发。
- Gate：数据集、随机种子、运行命令、版本、真实值及失败数可复现；前端可访问性/性能/媒体质量问题记录。

## G8：交付、审查和汇总
- 最终合并/发布前与用户授权边界核对；生成开发/启动手册、架构图、真实验收证据、项目实际状态、未解决问题和未来计划。
- Gate：`17_验收及缺陷处理.md` 所有硬性条目有明确 PASS/FAIL/BLOCKED，而不是“已完成若干模块”。

## 强制迁移原则
- 每个 Gate 后保留检查点和可运行状态；旧 API/API 数据、配置与媒体不盲删。
- 对表迁移采用 expand → migrate → contract，只能在证实旧代码已无依赖后清理（且破坏性删除需另行授权）。
- 前端采用按路由替换策略，先实现兼容 adapter，再迁移页面；旧页面至多成为 legacy 页面，不能丢访问。
- 本地 Feature Flags：`V2_STUDIO_ENABLED`, `AGENT_PROVIDER_MODE`, `WORKFLOW_ENGINE_MODE`, `EXTERNAL_VIDEO_ENABLED`（默认 false）、`PUBLICATION_ENABLED`（默认 false），具体变量名依代码规范确定。

## “连续开发”在权限边界内
Sol 可在授权工作区自行检查、编码、调试、补测试、提交可回滚修改并持续到 G8。卡在外部付费调用、用户凭据、不可逆删除、生产数据库或发布时，优先完成不受影响的后续工作，集中记录需用户决策事项；不能无授权操作，更不能把阻塞伪装为通过。

## 决策门禁优先于时间或额度
不要写“保证 5 小时做完”或“额度用完自动恢复”等不可控承诺；以测试达标和可交付代码为进度标准。
